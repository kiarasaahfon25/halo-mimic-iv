# HALO on MIMIC-IV: Evaluating Synthetic EHRs for Downstream Prediction

This repository trains [HALO](https://github.com/btheodorou/HALO_Inpatient) (Theodorou et al., 2023), a hierarchical autoregressive language model for synthetic longitudinal EHRs, on MIMIC-IV inpatient diagnoses. It then measures how useful the synthetic data is: downstream classifiers are trained on real data and on synthetic data, both are tested on the same held-out real patients, and performance is compared overall and by age group and sex.

Three prediction targets are supported, each with its own HALO model and synthetic dataset:

| Target | Description |
|---|---|
| `labels` | 25 HCUP CCS benchmark phenotypes (ICD-9 and ICD-10) |
| `mortality` | In-hospital mortality |
| `readmission` | 30-day readmission, excluding transfers |

## Data

This project uses [MIMIC-IV v3.1](https://physionet.org/content/mimiciv/3.1/) (`hosp` module: `admissions`, `diagnoses_icd`, `patients`). Access requires PhysioNet credentialing and a signed data use agreement.

**No MIMIC-IV data, derived datasets, synthetic records or trained models are included in or distributed through this repository.**

Set `mimic_dir` in `build_dataset.py` to the location of your MIMIC-IV `hosp` folder.

## Reproducing the experiments

Run from the repository root. Steps 2–5 are repeated for each target (`labels`, `mortality`, `readmission`).

```bash
# 1. Build patient records, labels and train/val/test splits (shared by all targets)
mkdir -p data
python build_dataset.py

# 2. Train HALO
python train_model.py --target labels

# 3. Plot loss curves
python plot_losses.py --target labels

# 4. Evaluate HALO on the real test set and generate a synthetic dataset
python test_model.py --target labels

# 5. Train classifiers on real vs. synthetic data and test on real data
python evaluate_synthetic_training.py --target labels
```

Results are written to `results/` and model checkpoints to `save/`.

<details>
<summary><b>Implementation details</b></summary>

**Dataset (`build_dataset.py`)**
- One record per patient. Each admission is a visit containing its ICD-9 and ICD-10 diagnosis codes. Patients keep at most their last 46 visits, which fits HALO's 48-position context.
- Phenotype labels come from `hcup_ccs_2015_definitions_benchmark.yaml` (ICD-9) and `ccs_benchmark_icd10_codes.csv` (ICD-10). The ICD-10 file is generated by `convert_benchmark_to_icd10.py` following the [HiSGT](https://github.com/jameszhou-gl/HiSGT) conversion.
- Readmission ignores next admissions that start less than 1 hour after discharge (or overlap it) and internal psych transfers.
- Splits: 80/20 train/test, then 90/10 train/validation, with seed 4.
- The printed vocabulary size must match `code_vocab_size` in `config.py`.

**HALO (`config.py`, `train_model.py`, `test_model.py`)**
- 12 layers, 12 heads, 768-d embeddings, batch size 48, 50 epochs, learning rate 1e-4. The best checkpoint is chosen by validation loss.
- One synthetic patient is generated per real training patient. Generation saves progress periodically and resumes if interrupted.

**Downstream evaluation (`evaluate_synthetic_training.py`)**
- Classifier: a 2-layer bidirectional LSTM, one per label.
- Training data: balanced samples of 10,000 patients from the real training set and from the synthetic set, each run through 5-fold stratified cross-validation.
- Testing: every fold is tested on the same balanced sample of 2,000 real test patients.
- Metrics: accuracy, precision, recall, F1, AUROC and AUPRC (mean ± std over folds).
- Subgroups: F1 by sex and by age group (18-39, 40-64, 65-79, 80+). A group with no actual positives gets F1 = `None`.

**Other scripts**
- `benchmark_sampling.py`: benchmarks synthetic generation speed.
- `check_icd.py`: checks how many admissions each phenotype covers in ICD-9 vs. ICD-10.

All scripts use random seed 4.

</details>
